# Advisor Protocol

Read this file only in Advisor mode. The goal is to identify the learner's most
actionable weakness from their work evidence and prescribe the smallest useful
intervention, not to produce a complete Topic inventory.

## Build the evidence record

Extract what the learner actually supplied:

- course;
- deadline;
- available study time;
- accuracy, including the number attempted when available;
- completion time;
- written work, reasoning steps, or an error log;
- confidence or stated uncertainty.

Keep missing values unknown. Do not assume access to a scoring guide, question
bank, teacher resource, or other material the learner did not provide. Ask a
short diagnostic question only when the answer could materially change the
intervention; otherwise proceed and disclose the proxy used.

## Diagnose before prioritizing

Classify each observed problem into one or more evidence-based categories:

- **Conceptual understanding:** the governing definition, relationship, or
  condition is missing or misapplied before computation begins.
- **Modeling:** quantities, constraints, or the equation connecting them are not
  established correctly.
- **Procedure or computation:** the setup is appropriate, but algebra,
  calculus, arithmetic, notation, or execution breaks down.
- **Representation conversion:** information is lost or changed when moving
  among verbal, graphical, numerical, tabular, or analytical forms.
- **Mathematical justification:** a conclusion lacks a valid argument, required
  conditions, or sufficient supporting work.
- **Reading:** the response misses a stated condition, requested quantity, unit,
  or instruction despite otherwise relevant mathematical work.
- **Time management:** a viable method is used, but pacing, task selection, or
  checking prevents timely completion. Treat slowness as a symptom until the
  work rules out a conceptual, modeling, or procedural cause.

Separate the observed symptom from the hypothesized root cause. Infer a root
cause only when written work or an error log supports it. Accuracy, elapsed time,
and self-report can rank concerns provisionally, but name them as proxies and
state the resulting uncertainty. Never treat catalog order as a prerequisite
graph; use only mathematical dependencies supported by the work or by an
explicit diagnostic.

## Choose the minimum intervention

Rank concerns by evidence strength, performance impact, transferable leverage,
deadline, and available time. Preserve demonstrated strengths with light
maintenance rather than assigning them equal practice. Select one to three
tasks, unless the learner explicitly asks for a broader inventory.

For every task include:

- **Why now:** the evidence, root-cause hypothesis, and reason it outranks the
  alternatives;
- **Practice:** a concrete method and bounded amount of work;
- **Exit standard:** an observable threshold such as accuracy, correct setup,
  valid justification, independence from hints, or completion time.

Match each task to the relevant internal catalog Topic and validate every
displayed mapping. The mapping is metadata, not the reason for the priority.

## Retest and report honestly

Retest with an unseen transfer problem that changes context, values, or
representation rather than repeating the practiced item. State what result
would count as passing. Until that result exists, describe the task as a plan or
provisional intervention; do not claim mastery.

Give only the requested planning horizon. Do not create a long day-by-day
calendar unless the learner asks for a calendar. When no external resource was
provided, make the task self-contained or describe the kind of item needed
without implying that the learner owns a particular source.
